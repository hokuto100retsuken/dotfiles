コードレビューを実行する。引数あり（URL / PR番号）ならそのPRを、なければ現在のブランチ差分をレビューする。

## 引数

- `$ARGUMENTS` が空 → 現在ブランチの差分レビュー（下記）
- `$ARGUMENTS` に URL または PR番号が含まれる → **`pr-review` スキルに委譲する**

## 引数あり: 他人の PR をレビューする

`pr-review` スキルを起動し、`$ARGUMENTS` を渡して**手順2（対象の特定）以降**を実行する。
依頼の列挙（手順1）は対象が決まっているので飛ばす。

**このコマンドに手順・観点リストを書き写さない。** 実体は `pr-review` 側の1つだけにする。
以前はここに手順と観点リストを直書きしていたため、`pr-review` にだけ入った
「指摘を絞る2段（機械的な足切り＋反証エージェント）」と「投稿後の反映件数の検算」が
このコマンド経由では効かず、誤指摘をそのまま下書きに載せる事故が起きた
（実測: 1 PR で3件出して3件とも撤回）。

`pr-review` が入っていない環境では、そのことを伝えて止まる。手順を思い出しで代用しない。

## 引数なし: 現在ブランチの差分レビュー

1. base ブランチを特定（`git symbolic-ref refs/remotes/origin/HEAD` → 無ければ master / main）
2. `git diff <base>...HEAD` と `git status` で差分を取得
3. `pr-review` の `references/checklist.md` を開き、観点を1項目ずつ当てる。
   思いつきでレビューしない
4. 指摘は `pr-review` 手順7a で機械的に足切りする（根拠が書けない / 既存に同じパターンがある /
   差分外 / nit）。反証エージェント（7b）までは回さなくてよい
5. 問題があれば具体的な修正案を提示、なければ「LGTM」と伝える

## 関連

- `pr-review` — PR レビューの本体。手順・観点リスト・投稿までを持つ
- `pr-review/references/checklist.md` — 観点リストの唯一の実体
