# 失敗学習ループ

## 記録するタイミング
以下が起きたら記録する。ただし本筋の作業の途中で割り込まず、作業の区切りかセッション終了時にまとめて記録する:
- ユーザーから作業のやり方を訂正された
- PRレビューで指摘を受けて修正した
- 同じエラーで2回以上手戻りした

## 記録フォーマット
`~/.claude/projects/<project-hash>/memory/` に1失敗1ファイルで保存:

```
### [タイトル] (YYYY-MM-DD)
- **状況**: 何をしようとしたか
- **失敗**: 何が間違っていたか
- **正解**: 正しいアプローチ
```

PRレビュー由来の学びは `pr-review-lessons.md` にまとめて追記する。

## 昇格メカニズム
- 別プロジェクトで同じ失敗・同種の指摘が再発したら、`~/.claude/rules/`（dotfilesの `claude/rules/`）へ昇格を提案する
- 昇格時はプロジェクト固有の文脈を削ぎ、汎用ルールとして1〜3行に圧縮する
- 昇格したらmemory側のファイルは削除する（二重管理しない）

## 記録するときの作法
- **想起トリガーを本文に書く**: 「〇〇の話題が出たらこれを想起する」の一文を入れ、発火キーワードを description にも含める。想起は description ベースの判定で100%ではない。確実に発火させたいものは memory ではなく hook を選ぶ
- **frontmatter の `#` と `: ` は必ずダブルクォートで囲む**: YAML は引用符なしの値の ` #` 以降をコメントとして捨てる。description が切れた記憶は事実上呼び出されない。issue / PR 番号を書く習慣があるため頻発する
- **ファイル名は `name` の値と一致させる**: 不一致だと `[[リンク]]` が切れる
- **節目で自分から拾う**: タスク完了時・話題の区切り・セッション終了前に、保存価値のある学びがないか一度見て提案する。ただし今後の振る舞いが変わるものに限る（無価値な記憶を増やさない）
- **「学びある？」に反射的に「ない」と返さない**: 直前1ターンで見れば「ない」が正しくても、単位を今日全体・セッション全体に広げて問い直す
