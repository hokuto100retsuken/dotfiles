# モデルの役割分担

- 考える・議論を深めるのは Opus（メインセッション）が担当する
- 調査は Sonnet の subagent に任せる。ただし subagent は起動のたびにフルコンテキストを読み直しトークンを大きく消費するため、**複数箇所にまたがる調査・独立した重い作業に限定**する。単発の検索・軽い確認・小さな叩き台はメインセッションで処理する（subagentに投げない）
- 議論を深めたいときは、Sonnet にディフェンス（防御・擁護）、Opus がオフェンス（攻撃・批判）を担当して議論させ、不足分を洗い出す。**このループは重要な論点に絞り、1〜2周で打ち切る**（頭打ちまで無制限に回さない）
- 洗い出した不足分は再調査（Sonnet）または再考（Opus）に回す

## subagent のモデルは呼び出し側で必ず明示する

agent 定義（`researcher` / `spec-checker`）を使うときは定義の `model` が効くので指定はいらない。
**`general-purpose` に投げるときは `model` を省略しない。** 省略すると親のモデルを継承し、
同じ役目でも実行のたびに違うモデルになる。

- **レビュー・反証は Opus**。特に反証役は指摘を投稿するか捨てるかを決めるので、
  モデルが揺れると投稿の基準そのものが実行ごとに変わる
- 実測（2026-09-09）では PR レビュー役が fable 16 / opus 10 / sonnet 6 / 未指定 3 に割れていた

## Fable を advisor として常駐させる（既定）

`advisor` は **main モデルが必要だと判断したときだけ呼ぶサーバー側ツール**。
Fable を advisor にしておくと、メインを Opus のまま「疑う役」だけ Fable に出せる。

```
/advisor fable            セッション中に有効化・切替
claude --advisor fable    起動時に指定
settings.json の advisorModel: "fable"   永続（既定はこれ）
```

実測・仕様（`claude 2.1.282` のバイナリで確認）:

- **advisor は main と同等以上の能力が要る。** main を Fable にすると advisor は発動しない
- **一度宣言すると `/clear` か `/compact` までモデルは固定**。有効・無効の切替は即時効く
- **追加トークンを使い、usage credits に課金される。** 毎ターン走るわけではなく呼んだ分だけ
- 止めたいときは `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1`

### 呼ぶタイミング

①と③はツール側の指示に組み込み済み。**②はこちらで足している。**

| # | タイミング | 問い |
|---|---|---|
| ① | 実質的な作業に入る前（書く・解釈を確定する・仮定の上に積む前） | このアプローチで本当にいいか |
| ② | **同じエラーで2回以上手戻りしたとき** | そもそも掘る場所を間違えていないか |
| ③ | 完了扱いにする直前 | 見落としがないか |

- ①の「オリエンテーション」（ファイルを探す・ソースを取る・現状を見る）は実質的な作業に入らない。
  先に見てから呼んでよい
- **③は呼ぶ前に成果物を durable にする**（ファイルを書く・保存する・コミットする）。
  advisor の応答には時間がかかり、その間にセッションが落ちると未保存のものは消える
- ②は `failure-learning.md` の「同じエラーで2回以上手戻り」と同じ閾値

advisor は反証役であって決定者ではない。**採否はメインセッションが決める**
（`pr-review` の反証エージェントと同じ扱い。判断に迷ったら反証側に倒すのはあちらの話で、
advisor の指摘は根拠を見てから採る）。

## effort の配分

`low` / `medium` / `high` / `xhigh`（`max` はセッション指定のみ）。

| 層 | effort | 置き場所 |
|---|---|---|
| メインセッション | `high` | `settings.json` の `effortLevel` |
| 探す・列挙する調査（`researcher`） | `medium` | エージェント定義の `effort` |
| 判断が混ざる調査（`spec-checker`） | `high` | 同上 |

- `/effort` での変更は**そのセッション限り**。恒久的に変えるなら `settings.json`
- `general-purpose` に投げるときは `model` と同様に **effort も明示する**。
  省略すると親を継承し、同じ役目でも実行のたびに変わる

## Fable をメインに切り替える場面

advisor で足りず、**Fable 自身に手を動かさせたい**ときはメインを切り替える。
API 料金が Opus の2倍（入力 $10 / 出力 $50 per MTok、Opus は $5 / $25）で、
1ターンが数分に伸びることがあるため常用しない。以下に当たったら切り替える。

- Opus で2回試して詰まった、または判断が割れて結論が出ない設計判断
- 長時間の自律作業（大規模リファクタ、複数リポジトリにまたがる移行）
- 難度の高い推論が要る調査（仕様の矛盾の切り分けなど）

切り替え方はメインセッションが `/model`、subagent は Agent の `model: "fable"`。
**Fable に投げるときは手順を細かく縛らない**（過剰に prescriptive なプロンプトは質を落とす）。
切り替えたら理由をユーザーに一言伝える。

**使用リミットに達したら Fable を使わない。** 利用上限・レート制限を示すメッセージが出たら、
そのセッションでは以降 Fable に切り替えない。Opus に戻して作業を続け、
リミットに達した事実と Opus で続けることをユーザーに一言伝える。
**リセットを待って作業を止めない**（待つかどうかはユーザーが決める）。

## 最初から Opus で投げる調査

Sonnet に向くのは「探す・列挙する・場所を特定する」調査。以下は判断が混ざるので最初から Opus で投げる。

- 仕様と実装の突き合わせ（`spec-checker` は Opus 指定済み。`researcher` は Sonnet）
- 複数の解釈があり得る問いへの結論出し、設計方針の比較
- 「なぜこうなっているか」の推定を含む調査

## 受け取った調査結果は検収する

subagent の結論をそのまま採用しない。**キーとなる1〜2点だけ自分で確認する**（`grep` 1発でよい）。
合わなければ全体を疑う。以下は不適切のサイン。

- 結論に `file:line` の根拠が付いていない
- 挙げているファイル・関数・カラムが実在しない
- 「おそらく」「〜と思われます」が結論になっている（推測で埋めている）
- 依頼した範囲の一部しか見ていない（リポジトリ・ディレクトリの取りこぼし）
- 突き合わせを頼んだのに片側しか読んでいない
- 件数を聞いたのに概算しか返っていない

## 不適切だったときのエスカレーション

**同じ内容を同じモデルに投げ直さない。** 原因で切り替え先を変える。

| 症状 | 対応 |
|---|---|
| 範囲の取りこぼし・事実の誤り | 同じ範囲を Opus の subagent に投げ直す（Agent の `model: "opus"`） |
| 判断・解釈の誤り | subagent に投げ直さず、メインセッション（Opus）で直接処理する |
| Opus でも結論が出ない・判断が割れる | Fable に上げる（`/model` または Agent の `model: "fable"`）。リミット到達後は上げずに Opus で続ける |
| 一部だけ欠けている | 欠けた部分だけ追加で投げる。全部やり直さない |

モデルを切り替えたら、**その事実と理由をユーザーに一言伝える**（黙って上げない）。
同じ調査で2回エスカレーションが必要になったら、subagent に投げるのをやめて自分で調べる。
