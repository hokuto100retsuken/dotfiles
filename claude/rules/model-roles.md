# モデルの役割分担

- 考える・議論を深めるのは Opus（メインセッション）が担当する
- 調査は Sonnet の subagent に任せる。ただし subagent は起動のたびにフルコンテキストを読み直しトークンを大きく消費するため、**複数箇所にまたがる調査・独立した重い作業に限定**する。単発の検索・軽い確認・小さな叩き台はメインセッションで処理する（subagentに投げない）
- 議論を深めたいときは、Sonnet にディフェンス（防御・擁護）、Opus がオフェンス（攻撃・批判）を担当して議論させ、不足分を洗い出す。**このループは重要な論点に絞り、1〜2周で打ち切る**（頭打ちまで無制限に回さない）
- 洗い出した不足分は再調査（Sonnet）または再考（Opus）に回す

## 最初から Opus で投げる調査

Sonnet に向くのは「探す・列挙する・場所を特定する」調査。以下は判断が混ざるので最初から Opus で投げる。

- 仕様と実装の突き合わせ（`spec-checker` は Opus 指定済み。`researcher` は Sonnet）
- 複数の解釈があり得る問いへの結論出し、設計方針の比較
- 「なぜこうなっているか」の推定を含む調査

## 受け取った調査結果は検収する

subagent の結論をそのまま採用しない。**キーとなる1〜2点だけ自分で確認する**（`grep` 1発でよい）。
合わなければ全体を疑う。以下は不適切のサイン。

- 結論に `file:line` の根拠が付いていない
- 挙げているファイル・関数・カラムが実在しない
- 「おそらく」「〜と思われます」が結論になっている（推測で埋めている）
- 依頼した範囲の一部しか見ていない（リポジトリ・ディレクトリの取りこぼし）
- 突き合わせを頼んだのに片側しか読んでいない
- 件数を聞いたのに概算しか返っていない

## 不適切だったときのエスカレーション

**同じ内容を同じモデルに投げ直さない。** 原因で切り替え先を変える。

| 症状 | 対応 |
|---|---|
| 範囲の取りこぼし・事実の誤り | 同じ範囲を Opus の subagent に投げ直す（Agent の `model: "opus"`） |
| 判断・解釈の誤り | subagent に投げ直さず、メインセッション（Opus）で直接処理する |
| 一部だけ欠けている | 欠けた部分だけ追加で投げる。全部やり直さない |

モデルを切り替えたら、**その事実と理由をユーザーに一言伝える**（黙って上げない）。
同じ調査で2回エスカレーションが必要になったら、subagent に投げるのをやめて自分で調べる。
