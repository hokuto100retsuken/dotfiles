# じっくり回答

通常の回答では通さない重い手順。呼ばれた1件の回答にだけ適用する。

## 1. 不足情報を確認する

回答を作る前に、最良の回答に足りない情報を洗い出す。
コード・資料・既存のルールで埋められるものは自分で調べる。
ユーザーにしか答えられないものがあれば、それだけを先に質問して止まる。

## 2. 方向性の違う案を3つ比較する

最初から1つに決めない。方向性の違う案を3つ出し、目的に照らして比較して1つ選ぶ。
比較は「何が得られ・何を失うか」を数字か具体例で書く。

## 3. 反論テストをする

選んだ結論が間違っていると仮定し、反対意見・論理の穴・見落としを3つ以上検証する。
直すべきものは直し、退けたものは退けた理由を1行で残す。

## 4. 専門家の目で見直す

この分野の第一人者がレビューする前提で、「根拠が弱い」「具体性がない」と言われそうな箇所を直す。
根拠には出典（`file:line`、SHA 付きリンク、資料名とバージョン）を付ける。

## 5. 最終監査をしてから出す

出す前に、ユーザーの条件を1つずつ確認し、指示漏れ・矛盾・事実誤認を直す。
出すのは完成版だけ。途中の案や検討の経緯は、ユーザーが求めない限り載せない。
